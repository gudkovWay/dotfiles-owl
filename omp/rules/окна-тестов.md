# Окна тестов

Запрос на изменение desktop-инструмента включает самостоятельный конечный запуск
и проверку отдельного экземпляра по `rule://no-autotests`, §6а. Не ждать отдельного
«создай стенд» или апрува тестового конфига. Процедура — `skill://desktop-sandbox`;
она выбирает достаточный режим, а не требует нового compositor для каждого окна.
При недоступной/неотрисовываемой поверхности действует автоматический display
fallback по `rule://no-autotests`, §6б, и `skill://desktop-sandbox`, независимо
от времени суток. Скрытый workspace не гарантирует свежие кадры.

Терминалы и окна, открываемые для тестов и проверок, никогда не должны
появляться на рабочих столах человека. Основной маршрут и подстраховка:

1. `/home/q/.local/bin/agent-app -- <команда> …` запускает отдельный процесс
   в текущем guarded scope, без `uwsm app`. OMP extension передаёт в bash
   `OMP_GUI_KEY`: session ID + agent registry ID → `special:omp-<ключ>`.
   `config.silent` определяет владельца на `window.open_early`, размещает окно
   с `follow=false` и подавляет map-focus; workspace не изолирует профиль/IPC.
   В уже открытой сессии без hook передай собственный `--session <ID>`
   и `--agent <registry-ID>` (main — `Main`). `--dry-run` показывает маршрут;
   настоящий запуск отказывает, если персональный маршрут не загружен.

   Kitty по-прежнему запускается отдельно с `--class agent-test`,
   не через `kitten @ launch` в живой инстанс и не с `--single-instance`.
   `agent-test`/`aquamarine` без ключа сохраняют общий `special:agent-tests`.

2. `hypr-agent-guard` — резервная маршрутизация по тому же ключу и точному
   адресу окна, без переключения стола. `pult-session` не переназначается.
   Guard не заменяет размещение при открытии и не даёт права закрывать
   окна/процессы по одному лишь workspace ID.

3. **Живая оболочка человека — не стенд.** Панели, бары, попауты и OSD
   работающего noctalia (`noctalia msg panel-open|panel-toggle`, включение и
   перезагрузка плагинов ради «посмотреть»), как и скриншоты его экрана
   (`grim` без явной просьбы), — это те же окна на рабочем столе, только мимо
   правила про класс: у layer-shell поверхности класса нет и на скрытый
   воркспейс её не увести.

   Для такой проверки нужен отдельный compositor по `skill://desktop-sandbox`,
   не запуск второй оболочки на special workspace живого compositor. Существующая
   обёртка `/home/q/.agents/skills/desktop-sandbox/scripts/vd-run.sh` не является
   полной изоляцией: HOME, UID, /proc и bus могут остаться общими. Проверку путей,
   IPC, geometry, захвата и teardown выполнять по скиллу, не дублировать процедуру.

Видимые окна на активных столах, поверхности живой оболочки и снимки его
экрана — только по явной просьбе человека.

Само по себе разрешение на live-preview не разрешает reset профилей, общие
конфиги/палитры, user-manager environment или persistent plugin/CLI install.
Успешная команда, новый профиль и `ok` сами по себе не доказывают сохранность.

## Доказательство через живую поверхность, а не через количество ревью

Для UI/runtime/media-работы верификация обязана упражнять реальную
пользовательскую/рантайм-поверхность: запустить программу, открыть изменённый
экран, воспроизвести сценарий, снять кадр в песочнице. Тогда ещё один статический
ревью поверх ревью поверхности проверку не заменяет — «перечитал код ещё раз» не
считается проверкой.

Нативный сценарий изменённого desktop-инструмента, настроенный headless E2E и
штатный owned headless профиль web UI (`wt ui`) разрешены в пределах
`rule://no-autotests`. Ввод и capture направлять в owned поверхность, не в текущий
фокус человека. Существующий пользовательский процесс, его конфиг, профиль и IPC
не заменять ради проверки. Запуск и все потомки — под общим resource guard.
Видимые окна, личный desktop и интеграция с живыми сервисами этим не разрешаются.

Без доступной/разрешённой живой поверхности явно помечать именно её
**unverified**; успешные unit/integration-тесты не доказывают рендер, фокус,
свайпы или native unload. Если выполнен штатный E2E, перечислить реально
упражнённые сценарии, не обобщать на весь UI. Не заменять недоступную
поверхность дополнительным статическим ревью и не запускать широкую волну
имплементации/ревью в предположении, что всё работает.
